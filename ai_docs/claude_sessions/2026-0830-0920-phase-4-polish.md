# Session: Phase 4 — Polish

Session: 4f298392-23de-40a5-b6b9-95c469be7ffe
Date: 2026-08-30

Phase 4 of `ai_docs/plans/interactive-tutorial-plan.md`. Phase 3 shipped
eight chapters that the engine could only run one at a time, from the
top, in silence. This phase made the tutor a curriculum rather than a
chapter player — and closed every open item Phase 3 left behind.

## One structural change paid for four features

`tutor.Run` is a **chapter loop** now. A new `tutor` struct holds the
curriculum, the progress store and the writers; its `chapter` method
builds a sandbox, a session and an engine, runs `repl.RunOptions`, tears
the playground down, and returns the next chapter index (-1 to stop).

The alternative — swapping the lesson under a live session — was never
really on the table. A chapter is a clean slate: chapter 5 has its own
fixtures, and a student arriving there holding chapter 2's variables,
files and working directory would be debugging the tutor instead of
learning the language. So a chapter switch is a teardown and a rebuild,
and the engine, which cannot perform one, only *asks*:

```go
// jump is the chapter index `:next` / `:menu N` asked for, or -1.
jump int
```

`Done` ends the loop; `Run` re-enters with the new index. That one
restructure closed four Phase-3 open items at once.

**`:next` and `:menu N` jump for real.** `:menu` alone still lists (with
`▸` on the current chapter, now matched by index rather than by ID);
`:menu 4` jumps, and validates first, so `:menu 40` is answered rather
than obeyed. `:next` also works mid-chapter — a student who has had
enough of jobs can move on, and the place they left is already saved.
The announcement prints *before* the rebuild, while the old panel is
still on screen, so "where did my files go?" is answered before it can
be asked.

**Chapter 2 turns `--explain` on itself.** The session is built per
chapter now, so the flag is just a field:

```go
if l.Explain {
    opts.Explain = io.Discard
}
```

`io.Discard`, not a real writer, and that is the interesting half.
`--explain` has two sides: a line per classified chunk on the writer, and
the live verdict in the prompt's hint lane. Only the second belongs in a
lesson — the first would print a classification dump over every panel.
The REPL reads `Session.Explaining()`, which is "the writer is non-nil",
so discarding the stream turns on exactly the half chapter 2 is teaching.

**A finished chapter stops ending the session.** `Done` used to mean
"finished or quit." It now says:

```go
case e.quit, e.jump >= 0:
case e.finished && !e.hasNext() && !e.keepPending():
default:
    return 0, false
}
```

An outro that offers an action has to leave the prompt alive to take it.
With a next chapter, or a keepsake file still in the playground, the loop
stays at the prompt; with neither, the tutor closes itself as before —
which is also what keeps the single-lesson unit tests (no `chapters`
wired in) ending on their own.

**Resume went from a step to a chapter.** Bare `grsh tutor` now calls
`resumeChapter`, which scans the records backwards and takes the
**furthest chapter touched**, not the first one left unfinished. Those
differ for anyone who jumped: a student who ran `grsh tutor 6` and
stopped halfway wants chapter 6 back, not chapter 1 because they never
bothered with the shell basics. A finished furthest chapter carries on to
the next; a finished *last* chapter starts the curriculum over rather
than dropping the graduate back onto the completion banner. It takes
`load func(string) (Record, bool)` rather than a `Store` so the policy is
testable as the pure function it is.

## Two chapter-level directives

The lesson format grew a front-matter region with meaning:

```markdown
# Two languages, one prompt

explain: on
```

Only `explain:` and `keep:` are claimed there; every other line stays the
editor's commentary it has always been. That asymmetry with the
step-level parser (which rejects an unknown directive) is deliberate —
front matter is prose written for the next editor, and a paragraph
containing a colon must not take the whole curriculum down with it. A
*known* key with an unusable value (`explain: yes`) is still an error,
because silently ignoring it would leave an author wondering why the hint
lane stayed quiet.

## `:keep` — the one file worth more than the playground

Phase 3's open item: the capstone writes `report.grsh` into a directory
that is deleted on exit. The plan had it written into `~`; that stayed
rejected, because a tutorial leaving files in someone's home is a
surprise. So the outro **offers** it:

```
  you made report.grsh — it goes away with the playground.
  `:keep` saves it to your home directory (`:keep <path>` chooses where).
```

`:keep` resolves the destination the way a shell user expects — home by
default, `~` expanded, a directory argument taking the file's own name
(what `cp` would do) — writes `0755` because a saved script the student
cannot run is a souvenir rather than a tool, and **never overwrites**.
Writing into a home directory unasked is already pushing it; doing it
over an existing file would be indefensible, so a collision is reported
and `keepDone` stays false so the student can retry.

`keepPending()` is what holds the final prompt open, and it stats the
file per prompt: the file only exists after the step that writes it, so
the offer appears exactly when it becomes true.

Meta-command handlers now take the rest of the line (`func(e *engine, w
io.Writer, arg string)`), which is what `:menu 4` and `:keep ~/x` both
needed. An empty argument means "none given", not an error.

## Tests

- **`testdata/chapter01.golden`** — the golden transcript the plan asked
  for: intro, every panel, a miss, the hint the second miss earns, each
  tick, the outro. Only the tutor's own writer is captured (the session's
  stdout goes to the grading tee alone), so it is the engine's chrome and
  the chapter's words, not the local `ls`'s column widths. `e.width = 64`
  pins the rule, so it tests the renderer rather than the window. It
  catches what nothing else does: a lost counter, an unpadded rule, an
  outro that forgets to name the next chapter, prose that picked up a
  stray blank line. `-update` regenerates.
- **`chapters_test.go`** — navigation on a three-chapter fixture (engine
  behaviour shouldn't fail on a curriculum edit), the resume policy as a
  table, and `:keep` (saves, refuses to clobber, holds then releases the
  final prompt). Plus `TestCapstoneOffersTheScript`, which walks the
  *real* chapter 8: the `keep:` directive, the file `session save`
  actually writes, and the engine's stat for that name can drift apart
  with nothing else failing.
- **pty** — `TestTutorEndToEnd` now finishes chapter 1, `:next`s into
  chapter 2, and types there: `wc -l access.log` shows
  `shell · rule=default` in the hint lane *before* Enter, which is the
  `explain: on` directive proven end to end through a real terminal.
  `TestTutorResumesEndToEnd` runs two processes over one `$HOME` — the
  only way a resume test means anything — asserting
  "Resuming at chapter 1 (It's just a shell), step 2".

A caching gotcha found the hard way: the pty tests build the binary
*inside* the test, so `go test ./...` served a cached PASS for
`internal/repl` after a change to `internal/tutor` alone. Use `-count=1`
when the change is in a package the test only reaches through the built
binary.

## Also

- `:help` pads the command name *before* colouring it. Padding a string
  that already carries escape bytes counts them as visible columns, so
  every row lost its alignment by the width of an SGR sequence.
- The outro's closing line was split in two — one 79-column line under a
  76-column rule.

## Open

- **Phase 5 (optional): the web tour.** rweb + `grsh.NewSession` per
  visitor over the same lesson files. The embedding API's
  `Interrupt`/`Kill` and writer-based IO were built for it, and the
  chapter loop just proved a session can be built and torn down mid-run.
- **`:back` cannot cross a chapter boundary.** It stops at step 1;
  `:menu N` is the way back. Symmetric with `:next` would be `:prev`,
  which nobody has asked for yet.
- **Skips are not remembered.** `:progress` counts them for the current
  chapter only; the record has no field for them, so a resumed chapter
  reports zero. Fine while a skip is not a score, worth revisiting if
  the tutor ever grows a "what did I miss?" view.
- **The panel does not wrap.** Prose lines are printed as written, so a
  chapter author owns their own line lengths (FORMAT.md does not say so
  yet). A very narrow terminal wraps them raggedly.
